Vybe fleet map

Every Vybe agent, every dashboard it publishes, and what actually connects them. This page exists because there are four separate sites and fifteen live addresses between them, and no single front door.

Every link below returned 200 when this page was written. For whether each one is current, the agent board checks all six watched surfaces every four hours and goes red on a stale one.

The shared spine — what makes this one system

One mailbox
jeremy@vybe.health, through Composio. Marketsom drafts into it, Growsom sends from it. john@vybe.health is CC on everything, in-thread replies included. This is where the collisions came from.
One booking link
calendly.com/jeremy-vybe/30min. One active event type, "30 Minute Meeting". No other booking URL appears in Vybe work, and CI fails the build if one does.
One repository
jermrox/agency-agents. Revsom, Marketsom and the daily worker publish from main. Growsom works on its own branch.
One ownership file
OUTREACH-OWNERS.json assigns every contested organisation to exactly one agent, so two desks never approach the same partner.
One rulebook
VYBE-AGENT-STANDARDS.md, eight rules, binding on every agent with Vybe in its name. Each agent also has a charter in task / conditions / standards form.
Four gates
On every change: no non-Vybe account anywhere in Vybe work; outreach purpose and single ownership; divisions and runbooks consistent; the growth-scout tests. Plus the agent board, every four hours, against the live pages rather than the code.

The five agents and their dashboards

Revsom

Non-dilutive funding

Keeps a board of money Vybe can win without giving up equity, and drafts an application packet for each priority opportunity.

  • Funding boardEvery live opportunity, its close date and whether it needs SAM registration. agentrevup.netlify.app
  • ApplyThe drafted application packets, with the founder-held facts left as placeholders. agentrevup.netlify.app/apply
  • funding.json feedThe board as data. This is the file the agent board ages. agentrevup.netlify.app/funding.json
  • Funding trackerThe older standalone tracker view. agentrevup.netlify.app/vybe-funding-tracker.html

Email: none. Drafts only, submits nothing.

Marketsom

Marketing, and partner outreach to communities

Reads Vybe's own marketing numbers every morning, drafts the community outreach, and keeps the marketing site honest about what is and is not working.

  • Agent hubAudiences, targets, the targeting playbook and eval scores. agentmarksom.netlify.app
  • Daily briefingStart here each morning: meetings and deadlines first, then the numbers and the open problems. agentmarksom.netlify.app/briefing.html
  • Weekly scoreboardThe rolling seven-day picture. The overall update lives here, not in the briefing. agentmarksom.netlify.app/scoreboard.html
  • Partner boardWho has been contacted, who replied, what each one needs next. agentmarksom.netlify.app/partner-board.html
  • All reportsEvery written report and research file. agentmarksom.netlify.app/reports.html
  • vybe-marketing.json feedThe scoreboard as data. agentmarksom.netlify.app/vybe-marketing.json

Email: drafts only, never sends. Read-only on every analytics and ad account.

Growsom

Investors, and technical collaboration

Finds partnerships that cost Vybe nothing and would actually grow it — apps and builders locked out of the closing wearable APIs first — screens each one, and carries replies to John.

  • Target boardEvery ranked target with its lane, its evidence and its drafted first message. agentgrowthscout.netlify.app
  • data.json feedThe board as data, including the per-state counts. agentgrowthscout.netlify.app/data.json

Email: the only agent that sends — and only a numbered draft John has approved, or John's own wording.

Instasom

Instagram and Facebook

Pulls the real social numbers every morning, says honestly whether they are moving, and hands over the day's captions, a Reel script and a verified list of people to follow.

  • Social dashboardThe numbers, the follow list with tick boxes, and the day's content. instasum.netlify.app
  • all.json feedThe whole store as one file, which is what the dashboard reads. instasum.netlify.app/all.json

Email: the founder's own daily brief. No outreach, and never a direct message.

The daily worker

Product, funding rows, packets, decks

Ships one new app screen a day on a fixed rotation, adds verified funding rows, drafts an application packet, and on Mondays produces a pitch deck and the weekly report.

  • No dashboard gapIts output is code merged to main and rows that show up on Revsom's board. There is nowhere to look at what it has built.

Email: none. Touches no Vybe account at all.

What this map shows that no single dashboard does

The daily worker is invisible. Four of the five agents publish somewhere you can look. The one shipping the actual product does not, so its fourteen screens and seventeen application packets exist only as commits.
Growsom's data lives on a branch, not on main. Its target and follow-up files are not on the main line, so a check that joins both outreach logs can only run where both are present. That is why the single-ownership gate reports what it can see and names what it cannot.
Two agents, one mailbox, no shared memory. Marketsom and Growsom both write into jeremy@vybe.health and neither can read the other's working notes. The ownership file is the fix, and it is a file rather than a feeling precisely because memory did not hold.
Four sites is a choice, not a design. Each agent got its own Netlify project as it was built. Two deploy from git, two are pushed by API. That is why a repository fix updates nothing until the live page says so, which is rule 5 of the standard.
